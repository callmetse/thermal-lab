# A/B/C 对照与消融实验

## 1. 先回答三个问题

1. 同样的相机证据和模型，把计算放在 Pi、两端分担、全云端，哪个方案能更快给出**正确且新鲜**的结果？
2. 哪个方案更能承受手机热点、短时断网、多人／遮挡和长时间运行？
3. 数值 CLO/MET 估计的误差来自衣物／活动识别、上下文缺失、参考赋值，还是 LLM 输出？

当前已完成短回放位置对照、多人扩展和摄像头实拍联调，分别见 [实验结果.md](实验结果.md)、[实拍测试结果.md](实拍测试结果.md)。实拍各轮场景不同，不混作主对照；现场准确性、物理热点／PC断网和长时稳定性仍待测。

## 2. 主对照固定什么

- 同一段源视频，核对文件 SHA256；按原始时间节奏回放。用 `source_frame_id`、源 PTS、JPEG 哈希对齐，不能只按“该组第几条观测”对齐。
- 同一 YOLO 姿态、服饰和动作权重来源、输入尺寸、阈值、类别映射；相同 JPEG 证据。Pi 使用 NCNN，GPU 使用 PyTorch CUDA，后端差异另外检查。
- 公共 LLM 为同一 `qwen2.5:7b`，同一实际 digest／量化、固定提示词、temperature=0、seed=42、输出 token 上限。相同文本事实输入，不额外给某一组图片。
- 相同相机／回放源、分辨率、JPEG 质量、采样规则、预览 2 Hz。基准配置 15 FPS 采集目标、12 FPS 采样目标，**只是起点，不是测得的最佳值**。
- 当前统一长边 640／JPEG55，pose640／服饰512／B门控416，显式 `rect=False`。多人默认 `max_people=0`、不按身高筛人；配置和提示词变更前后的测量分开存档。
- 服饰分支当前来自复用代码，按源时间 1 Hz 更新并最多保留 2 秒；动作分支依赖其既有 16 槽／8 Hz 模型合同。单独记录缓存年龄和窗口覆盖，不因观测输出频繁就声称服饰每帧更新。
- A/B/C 依次运行；共享一台 Pi 的三组同时跑会争 CPU／相机，不能作为主结果。A→B→C、B→C→A、C→A→B 三轮轮换。分别报告冷启动与模型已加载后的稳态。

严格逐像素离线对照还应提前统一解码／JPEG 帧文件；新实时回放原型会在同一 Pi 上解码，但不同负载可能选择不同时间帧，哈希不同的样本不能当同输入结果。

## 3. 分阶段运行

| 阶段 | 做什么 | 合格依据 |
|---|---|---|
| S0 | 新 broker／控制台／隧道隔离检查 | 所有 topic、端口、卷、锁、服务名归本项目；旧服务未改；新服务无法订阅旧 broker |
| S1 | 无相机回放短跑，已用 12.7 秒源视频做每轮 15 秒、每组 1 次预热＋3 次测量；后续换长录像 | 三组均出现真实推理观测；7B 返回有模型标记的结果；没有加载模型时明确失败；stop 后不接受旧 run 结果 |
| S2 | 同源回放，每组 10 分钟，轮换 3 轮 | 生成指标表、负载与模型清单；单轮失败保留，不能从均值中偷偷删掉 |
| S3 | 手机热点，PC 断网，按相同场景重复 | Pi→两云→手机完整工作；记录实际网络、RTT、丢包／恢复；不能用降低发送 FPS 代替真正网络限速 |
| S4 | 人工标签与独立参考值 | 用留出人物／衣着／片段评价；未知覆盖率与准确率同时报告；有独立数值参考才计算数值误差 |
| S5 | 长时间与故障 | 至少一轮 2 小时，候选默认档再做 8 小时；短时中断／服务异常后恢复，并把所有结果标明实验条件 |

现场场景至少包括：无人→入场、静坐、站立、走动、坐下／站起转换、外套穿脱、上半身遮挡、多人交叉。增加“同姿态但交互物体／任务不同”样本，借鉴 P2。

## 4. 指标和读法

| 目标 | 必须一起报告的指标 |
|---|---|
| 速度 | 启动→首条视觉、启动→首条 7B；采集／编码／门控／云端排队／视觉推理／7B／显示代理的 p50、p95；真实活动变化→正确结果的更新时间 |
| 频率 | 相机实际帧率、选中率、发送成功率、接收率、实际视觉处理率、服饰更新 Hz、动作窗口覆盖、结构化观测 Hz、7B 完成 Hz、预览／页面刷新 Hz |
| 时效 | 结果基于哪一帧、衣物缓存年龄、最大结果空洞；跨机时钟误差未明确时不报完整 AoI 数字 |
| 稳定 | 崩溃次数、重连次数、恢复时间、误翻转率、unknown／拒答比例、有效结果覆盖、停止响应、迟到结果被丢弃的次数 |
| 准确 | 人物检出 P/R；衣物按类 F1；姿态／动作 macro-F1、混淆矩阵；活动转换事件召回与延迟；7B 事实错误率 |
| CLO/MET | 标准参考一致性与实测误差分列；数值输出覆盖率、MAE／偏差、误差分布；未获得真值写未测 |
| 资源 | Pi CPU／内存／温度／降频，GPU 利用率／显存，控制云负载，推理／预览／控制的字节分项，必要时主机网络计数器 |

本原型记录 MQTT 应用负载字节，**不是含 SSH、TCP、重传的实际计费流量**。正式报告还要采网络接口计数器。A 的手机预览流量必须算进去。

分段耗时使用同一机器单调时钟。控制台接收命令、观测、7B、浏览器 ACK 共用控制端时钟，可计算该段往返代理；这仍不是“相机曝光到屏幕发光”的真实延迟。**不允许用 `min(处理时间−采集时间)` 当时钟偏差校准，它同时包含最小网络／处理延迟，会把结果人为归零。**

## 5. 优先消融

先完成主对照，再一次改一项：

| 优先级 | 消融 | 依据／目的 |
|---|---|---|
| 1 | 相同视觉事实：确定性参考估计 vs 加 7B | 判断 7B 是否带来额外正确性／解释价值，以及延迟代价；规则回退不能计作 LLM 成功 |
| 1 | 姿态／动作 vs 加交互物体上下文 | 借鉴正式期刊 P2，针对同姿态不同任务的 MET 歧义；先确认预训练类表覆盖哪些物体 |
| 1 | 即时 vs 15 秒众数；再选 1／3／5 秒中间值 | P2 提供明确发表设置；同时看准确、误翻转和活动变化延迟 |
| 1 | 固定 8／12／15 FPS | 找出采样率、动作窗口有效率、AoI、CPU 和流量之间的关系；有余量再试 20／30，不先承诺跑满 |
| 2 | B 整帧门控 vs 原生高分辨率人体 ROI | 判断能否减少传输并提高衣物细节；边缘检测漏人造成的最终漏检必须算入 |
| 2 | 无人时间占比 0／50／90% | B 的收益取决于空场景；合成空场与真实空场分开报告 |
| 2 | 不限应用人数 vs 3／10／20 人；人物远近和输入分辨率另测 | 解除旧三人过滤后测实际检出人数、延迟和漏检；人数上限仅作负载消融，不作为默认人为限制 |
| 2 | 二进制 JPEG vs 标准媒体管线 | 复用 GStreamer／MediaMTX；Pi 5 编码 CPU、网络与缓存各自计时 |
| 2 | 属性新鲜更新 vs 带 TTL 缓存 | 把“看起来稳定”和“真实变化后更新很慢”区分开；不要复用过期服饰／动作 |
| 3 | 多阶段视觉 vs 期刊单阶段联合模型 | P4；仅在拿到可验证代码和权重后运行官方样例，不自己临时复刻一套网络 |
| 3 | 文本 7B vs 同证据的 7B VLM | 借鉴 P8 的评估框架，但不借其 Gemini 数值；保持图像／片段证据、量化、提示词和时间预算一致 |

## 6. 哪些事情需要真实数据

当前复制的回放片没有人工真值，现有 v4 的标注 CSV 也未填，不能输出新工程的准确率。先收集 6–10 组衣着／动作片段作试点，并留出未参与选参数的人与片段；这只是试点规模，不是充分统计功效的保证。

每条标签关联源视频 hash、源帧／时间段、该人的边框或人工编号、可见衣物、完整衣着是否由本人确认、活动任务／强度、遮挡原因和参考来源。动作标签看时间片段，不能用一张图判断“刚坐下”。未知不直接从分母剔除：同时算条件准确率和所有目标上的有效覆盖／端到端正确率。
