# 新工程部署与验收

**当前服务器已经采用原生部署，请先读 [当前部署与操作.md](当前部署与操作.md)。** 本文件以下容器／用户服务组合是最初的备用部署设计，未在当前服务器执行；当前使用新 Supervisor，而非下列备用 worker@ 用户服务。不能并行执行来占用当前原生服务端口。旧项目服务不在两份操作单的启停范围。

## 1. 三个目录和两个必要条件

工程分别放到 Pi 的 `/home/pi/abc20261102`、GPU 的 `/root/abc20261102`、控制云的 `/srv/abc20261102`。其中 Pi/GPU 的 systemd 用户单元通过 `%h/abc20261102` 找工程，目录不能随意改。

先检查目标端口 `28883/28880/28434` 未被占用，确认 Docker/Compose、ARM/Python/CUDA 版本和 GPU 空闲显存。新 7B 会占显存，若旧任务占满，不得为了本实验杀旧进程；先保留新工程为待启动状态。软件隔离不代表 GPU 物理算力隔离。

当前 GPU SSH 已接通并完成真实部署。进入实拍还需确认相机可独立使用；回放不打开相机，不依赖这个条件。

## 2. 控制云：只启动新的 broker 和 Node-RED

用途：Pi/GPU 通过新 broker 交换数据，新 Node-RED 负责手机页面与独立日志。

先用 Node-RED 官方工具交互生成新 UI 密码的 bcrypt 哈希，密码不进仓库：

```bash
docker run --rm -it --entrypoint node-red-admin nodered/node-red:5.0.9 hash-pw
```

在 `/srv/abc20261102/deploy/.env` 写入 `ABC_UI_USER` 和 `ABC_UI_PASSWORD_HASH`，使用新值，不复制旧控制台密码。哈希含 `$` 时用 Compose 支持的单引号字面量保存，避免变量展开。

启动前先验证配置：

```bash
cd /srv/abc20261102
docker compose --env-file deploy/.env -f deploy/control.compose.yml config --quiet
docker compose --env-file deploy/.env -f deploy/control.compose.yml up -d
```

验收：只出现 `abc20261102-control` 的新容器；控制云监听回环 `28883` 和 `28880`；旧 MQTT／旧 Node-RED PID、端口、流程没有变化。若 Node-RED 提示 `/data/lab` 无写权限，仅修正**本项目新卷**的 UID 1000 所有权，不对旧数据目录执行递归 chown。

手机采用自己的 SSH 本地转发，把手机 `127.0.0.1:28880` 转到控制云 `127.0.0.1:28880`，再打开 `http://127.0.0.1:28880/lab`。SSH 客户端须支持本地端口转发。PC 可以关机；它不参与这条链路。以后若需要直接 URL，则另设本项目 HTTPS 域名／代理，不改旧项目入口。

## 3. Pi/GPU：新 venv、新隧道

用途：复用软件包的标准接口，但不修改旧 venv、旧启动器或旧模型服务。

在新目录中建立 venv。Pi 与 GPU 的 Torch wheel／CUDA 组合不同，先按各自主机支持矩阵安装；不要直接复制 Windows venv。当前Picamera2薄适配已经验证实机采集；系统 Picamera2 与所选 Python ABI 仍须核对。

```bash
cd ~/abc20261102
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-runtime.txt
.venv/bin/python -m pip freeze > results/environment-freeze.txt
```

Pi 的 A/B 使用 NCNN，还需在**新 venv**安装官方所需 NCNN 导出／运行依赖。B 的人体门控导出：

```bash
.venv/bin/python tools/export_gate.py
```

验收：产生 `assets/yolo11n_ncnn_model`，确认任务 `detect`、输入 416；使用相同样本比较 `.pt` 与 NCNN 的人体检出、框 IoU、人物门控决策。A 的 pose NCNN 是 640、服饰 NCNN 是 512，不能悄悄换输入尺寸后宣称只比较计算位置。

将 `deploy/worker.env.example` 复制为工程 `.env`，在本机 SSH 配置新增 `abc-lab-control` 别名，指向控制云，使用已授权的密钥认证。新隧道服务只转发 `28883`，不能复用旧 `11883` 隧道。手工调试命令为：

```bash
ssh -N -T -o ExitOnForwardFailure=yes -L 127.0.0.1:28883:127.0.0.1:28883 abc-lab-control
```

验收：Pi、GPU 的 `127.0.0.1:28883` 都连向新控制云 broker；PC 断开后仍连接。不要在同一机器同时启动手工隧道与同端口 systemd 隧道。

## 4. GPU：独立 7B 引擎

用途：三组共用一套固定 7B 参数，避免每帧触发生成或阻塞视觉线程。

```bash
cd /root/abc20261102
docker compose -f deploy/gpu.compose.yml config --quiet
docker compose -f deploy/gpu.compose.yml up -d
docker compose -f deploy/gpu.compose.yml exec llm7b ollama pull qwen2.5:7b
curl --fail http://127.0.0.1:28434/api/tags
```

验收：模型实际名字为 `qwen2.5:7b`，记录 digest、量化、参数规模、加载显存；新 Ollama 只使用 `28434`，没有访问旧 7B 的 HTTP 端口。模型未下载／显存不足时应明确失败，不自动换小模型。

容器镜像的可变标签只用于首次准备，正式测速前记录并固定 pull 后的 RepoDigest，A/B/C 期间不更新镜像。Node-RED `5.0.9`、Mosquitto `2`、Ollama `latest` 的可用性本轮已查询；仍需以部署机器实际拉取结果为准。

## 5. 三个适配进程

调试阶段，在各自的新目录运行；下列命令不会修改旧程序：

```bash
# Pi
.venv/bin/python -m lab.worker edge
```

```bash
# GPU：两个独立终端／用户服务
.venv/bin/python -m lab.worker cloud
.venv/bin/python -m lab.llm
```

长期运行时复用 systemd：将本项目 `deploy/abc20261102-*.service` 安装到各自 `~/.config/systemd/user/`。Pi 启动 `abc20261102-mqtt-tunnel` 与 `abc20261102-worker@edge`；GPU 启动独立隧道、`abc20261102-worker@cloud` 和 `abc20261102-llm`。用户服务开机持久化需检查该账号 linger 配置；不要写成已通过开机验收。

验收顺序：先 C 回放 30 秒，再 B，再 A。页面应出现同一 run 的预览、视觉事实、7B 成功／拒绝／失败状态。停止后不再显示该 run 的新结果，马上再开一轮时旧计时器不能停止新 run。新进程不能要求旧项目目录存在。

## 6. 从回放进入实拍

默认已复制一份旧回放到 `data/replay.mp4`，**未标注**，三机回放已跑通。USB OpenCV 与 CSI Picamera2 两种适配可选，实拍前确认设备号／相机类型和 Python ABI，再做硬件验收。

只有相机已空闲或分配了另一只相机时，才把新项目配置 `allow_camera` 改为 `true`。首次部署时旧v4占用相机；本轮已按用户授权停止旧系统并移交相机，当前状态以实拍报告为准。禁止为了隔离方便，把旧 v4 的相机流偷偷作为新项目的上游输入。

实拍验收：完整人物、头部无需特写、能看见下肢与衣物；多人交叉后 ID 仅作为会话内编号。单目远近大小不当成测距，像素速度不当成米／秒。

## 7. 取证与汇总

在控制云只导出本项目日志：

```bash
docker compose --env-file deploy/.env -f deploy/control.compose.yml exec -T console cat /data/lab/events.jsonl > results/events.jsonl
python3 tools/report.py results/events.jsonl --output results/summary.json
```

验收：每轮包含 command、source_open、vision_ready、真实 observations、llm、transport_stats；浏览器打开时应有 display_ack。`console_boot_id` 不同的进程计时不混算。汇总中的 `capture_to_display_ms` 在跨机校时未验证前保持空值。

7B 的数字守卫仅检查基础输出约束，**不是事实正确性的自动证明**。需要人工评价；失败或拒绝结果不能归入“正确预测”。

## 8. 只停止本项目

关闭新用户服务，或在对应目录使用：

```bash
docker compose --env-file deploy/.env -f deploy/control.compose.yml stop
docker compose -f deploy/gpu.compose.yml stop
```

两条命令分别在控制云／GPU 云执行，不必去旧项目“回滚”。保留日志与卷，不删除旧服务、不运行旧 `pi_switch.sh`、不使用 `pkill -f cloud_worker` 等宽泛命令。
