# 同一局域网的实时操作入口

当前地址：**http://192.0.2.11:28880/lab**。电脑、平板或手机连接与Pi相同的局域网后，在浏览器打开即可。直接打开 `http://192.0.2.11:28880/` 也会转到控制页面。

首次打开需要登录。账号和密码已交付到本机私有文件 `C:\Users\operator\.codex\secrets\abc20261102-console\login.json`，也可在控制云私有文件 `/etc/abc20261102/ui-login.json` 查看。凭据没有放入项目、报告或截图。Pi只保存登录哈希，位于项目外的 `/home/pi/.config/abc20261102/console-auth.env`。

## 怎么操作

1. 选A／B／C，来源选“摄像头实拍”，填写秒数。
2. 点“开始”。按钮旁会立即显示“正在启动”，随后显示启动结果；画面和识别会继续更新。
3. 点“停止”。停止后可更换组别再次开始。运行中会锁定组别／来源，避免把未生效的选择误认为已经切换。
4. B组检出人物后进行云端识别，门控阴性时仍发送状态预览。人物框／属性只依据当前帧已有证据显示。

聊天中 `.png` 结尾的是截图文件，不能在图上操作；上面的HTTP地址才是实时控制台。

## 实际部署

浏览器 → Pi局域网端口28880（Caddy）→ Pi自己的专用SSH隧道28881 → 控制云原生Node-RED回环28880 → 本项目MQTT／Pi／GPU。

Pi的 `abc20261102.service` 内新增 `console-tunnel`、`console-gateway`，由成熟Supervisor管理并自动重启。电脑只作为浏览器，不需要在电脑上开SSH转发。云端模型仍需要Pi能联网访问两台云；局域网入口并没有把模型搬回电脑。

控制云MQTT、已有A/B/C命名空间、视觉模型、7B和实验日志没有更换。旧系统仍保持关闭。控制云控制台仍只绑定回环，没有为此开放公网端口；Pi入口只接受内网地址并要求登录，HTTP及WebSocket都由Caddy处理。

## 已验证

- 真实Chromium通过Pi的LAN IP访问，实际点击“开始”，收到相机帧，再点击“停止”；不是仅调用后台接口。
- `/lab` 与 `/lab/` 两种地址均通过；开始、停止接口均返回200。
- 浏览器内单独模拟503错误时，按钮旁能显示错误；模拟没有修改实际服务器状态。
- Windows端直接访问该LAN地址并登录返回200。上述检查没有使用电脑本地SSH隧道。
- 检查文件：`results/lan-console-browser-checks.json`；页面实拍截图：`results/lan-console-live.png`。

本轮没有替用户操作物理手机。手机同网访问时使用同一个地址；若热点切换使Pi的IP改变，应使用新IP。Pi主机名为 `raspberrypi`，支持mDNS的设备也可尝试 `http://raspberrypi.local:28880/lab`，该别名没有纳入本轮验收。

## 官方依据

- [Node-RED Raspberry Pi官方文档](https://nodered.org/docs/getting-started/raspberrypi)：其他设备浏览器可通过Pi主机名／IP和端口访问。
- [Node-RED HTTP节点与Dashboard认证](https://nodered.org/docs/user-guide/runtime/securing-node-red)：使用其成熟HTTP认证机制，编辑器入口保持关闭。
- [Caddy官方reverse_proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy)：复用HTTP／WebSocket代理与流式转发，不自行实现媒体或WebSocket服务器。
- [Caddy 2.11.7正式发布说明](https://github.com/caddyserver/caddy/releases/tag/v2.11.7)：该版本修复前版的流中断问题。本轮ARM64官方工件已按其SHA512清单校验，记录在 `results/lan-caddy-provenance.json`。

网页入口改进不等于视频帧率优化。当前预览频率、视觉观测频率和7B更新频率仍分别记录，不把预览图片刷新数当作全部识别模型的Hz。
