## A/B/C

| 组 | Pi | GPU 云 |
|---|---|---|
| A | 姿态、服饰、ByteTrack、时序动作；上传结构化观测，预览留在Pi局域网 | 同一 7B 解释视觉事实 |
| B | YOLO 人物检测门控；有人时上传整帧 JPEG | 姿态、服饰、跟踪、时序动作＋同一 7B |
| C | 采集、固定采样、编码上传 | 全部视觉＋同一 7B |

B 的整帧门控没有替代云端 pose 内部的人体检测。有人常驻时未必划算；人体 ROI、空场景占比另作消融。动作需要连续时间证据，C 当前采用固定采样；稀疏语义关键帧另测漏检和窗口覆盖。

## 多人设置

新项目已去掉旧代码的“只留最大三人”和“身高至少占画面 18%”过滤。默认 `max_people=0`，表示不设应用层人数上限；`min_person_height_ratio=0`，不按人物大小丢人；输出置信度 `0.25`，YOLO 的 `pose_max_det=300` 可配置。ByteTrack 的现成关联逻辑保留。这个 300 是模型每帧候选上限，不代表已经验证能稳定识别 300 人。

人物会保留自己的框、临时跟踪 ID、骨架和可用属性。小人物也参与检测；衣物、姿态或动作证据不足时对应字段可未知，不因此把整个人删掉。多人数量与速度的实际结果单列在实验报告。

两台云都没有 Docker，当前使用新目录和新 venv 原生运行；不改旧 venv。Pi/GPU 直接连控制云，PC 不转发图像。软件隔离不能消除共享硬件的 CPU、GPU、温度和带宽竞争，正式实验需记录其他负载。

相机当前 `allow_camera=true`，旧采集器已停。IMX708广角摄像头由Picamera2独立采集640×480；当前目标30FPS，本轮约29.6FPS。A/B/C早期实拍记录仍单独保留。12.7秒户外操场回放仍独立保留。两种来源的数据不混算。

## 复用范围与当前边界

使用 Ultralytics、NCNN、ByteTrack、现有服饰／TCN 工件、Node-RED、Mosquitto/Paho、Ollama；`lab/` 负责分组、协议与记录，没有新造检测器或动作网络。Pi NCNN 已从同一 `.pt` 官方导出，见 [export_manifest.json](assets/export_manifest.json)。

当前 7B 是文本模型，接收三组相同结构的视觉事实；看图的 7B VLM 是另一个消融。当前 CLO/MET 数值尚未接入充分依据，输出为 `null`；已保留可见衣物的标准参考候选。**这部分还没有完成数值估计验证**，不能用衣物类别或坐／站姿态冒充真实热阻或代谢率。

主要目录：`lab/` 适配；`vendor/` 独立源码副本；`assets/` 权重；`research/` 联网证据；`tools/` 导出和汇总；`results/` 测量记录；`data/` 独立回放与待填标签。
