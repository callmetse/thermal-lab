# 成熟软件与传输方案

核查日期：2026-11-02。以下是能复用的软件能力，不是本项目已实测的性能。

| 组件 | 官方来源 | 本项目选择与边界 |
|---|---|---|
| Ultralytics + NCNN | [Pi 部署说明](https://docs.ultralytics.com/guides/raspberry-pi/) | Pi 基线使用已有 YOLO11 小模型，走官方导出／推理接口；不因为出现更新家族就同时换模型，导致位置对照失去可比性。GPU 使用相同 `.pt` 来源，后端不同需另做一致性验证 |
| ByteTrack | [Ultralytics 跟踪](https://docs.ultralytics.com/modes/track/) | 使用内置跟踪器；不自己实现多人 ID 关联。ID 只在单次会话中有效 |
| PaddleClas PULC / PP-Human | [PULC 属性说明](https://github.com/PaddlePaddle/PaddleClas/blob/release/2.6/docs/en/PULC/PULC_person_attribute_en.md)、[PP-Human](https://github.com/PaddlePaddle/PaddleDetection/tree/release/2.9/deploy/pipeline) | 有现成服饰属性识别；需要人体 ROI，且属性输出不是 CLO。丢弃任务无关的性别、年龄等属性 |
| MMAction2 | [STGCN++ 官方模型库](https://github.com/open-mmlab/mmaction2/tree/main/configs/skeleton/stgcnpp) | 使用官方配置和 checkpoint 作后续对照；先检查骨架布局、输入窗口与目标活动类，不为追求“现成”而错误拼接 |
| Node-RED | [官方部署文档](https://nodered.org/docs/getting-started/local) | 当前新目录原生部署，新 flow、新日志；复用其 HTTP、MQTT、文件节点。现有 Node-RED 不导入本项目流程 |
| Eclipse Mosquitto / Paho | [Mosquitto 配置](https://mosquitto.org/man/mosquitto-conf-5.html)、[Paho](https://eclipse.dev/paho/files/paho.mqtt.python/html/) | 独立 broker，控制 QoS1、图像 QoS0；当前仅回环和专用 SSH 隧道可达。所有隧道属于新项目 |
| Ollama + Qwen2.5 7B | [模型条目](https://ollama.com/library/qwen2.5:7b)、[生成 API](https://docs.ollama.com/api/generate) | 独立实例和模型存储；`qwen2.5:7b` 条目为 7.62B、Q4_K_M、约 4.7GB，属于 7B 档。数字是模型条目，不是实际显存测量。三组共用模型 digest／量化／提示词／生成参数 |
| GStreamer / MediaMTX | [appsink](https://gstreamer.freedesktop.org/documentation/app/appsink.html)、[MediaMTX 发布／读取](https://mediamtx.org/docs/usage/publish) | 媒体路径候选，之后与 JPEG 作独立消融；使用有界缓冲、按版本设置丢旧帧行为，不能保证所有编码格式、网络下都低延迟 |
| Reducto | [官方工件](https://github.com/reducto-sigcomm-2020/reducto) | 任务相关筛帧的研究工件，可借方法。先保住时序动作窗口；静止帧对服装可能冗余，对活动持续时间却未必冗余 |
| pythermalcomfort | [服装热阻](https://pythermalcomfort.readthedocs.io/en/latest/documentation/clothing.html) | 标准估计与物理计算优先用成熟实现；先确认输入、版本和适用条件，不重写热舒适方程 |

Pi 5 不应被默认当成带硬件 H.264 编码器的 Pi 4。参考 [Raspberry Pi 官方 H.264 编码白皮书](https://pip-assets.raspberrypi.com/categories/685-app-notes-guides-whitepapers/documents/RP-010033-WP-1-H.264%20encoding%20performance%20on%20Raspberry%20Pi%205_series%20computers.pdf)，软件编码可行，但需要实测与视觉推理竞争 CPU 的代价。换 SRT、RTSP 或 WebRTC 只是协议选择，不会自动消除编码、缓存、重传与浏览器显示延迟。

第一阶段保留简单且可记录的二进制 JPEG，避开 base64 膨胀；这只是起点。第二阶段用 MediaMTX／GStreamer 做相同输入、相同画质预算下的传输对照，报告完整上行字节、CPU、事件漏检与结果年龄，而不是仅比较包数。

## 补充：无需自行实现动作网络的候选

[Human-Falling-Detect-Tracks](https://github.com/GajuuzZ/Human-Falling-Detect-Tracks) 有 TSSTG 公开实现，README 列出七类（站、走、坐、躺、起身、坐下、跌倒）和预训练权重链接。已读取 README 与 `ActionsEstLoader.py`：30 帧骨架窗口、坐标归一化、额外中点关节和运动差分，使用 AlphaPose 来源骨架与 Le2i 数据。**未下载／验证 checkpoint，不是已部署组件，也没有确认它就是 P6 作者的原版工件。**

它可作为当前 TCN 类别缺口的后续成熟基线，但需先核对关节排列、采样率和模型许可；不整套照搬其较长采集队列，也不把跌倒分类模型直接叫作 MET 模型。
