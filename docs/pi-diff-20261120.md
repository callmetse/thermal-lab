> old repository, not the current tree. The device archive under `deployments/pi-20261120/` and the

Read-only comparison between this repository and the live Raspberry Pi at `192.168.5.8`
(`/home/pi/abc20261102`, `/home/pi/mm_audio_v1`, `/home/pi/env_sensor_v1`). Nothing on the
device was modified. The archived copy of the device tree is under `deployments/pi-20261120/`.

## Method

The Pi was reached over SSH. A `find` with the source extension filter used for this repository
produced a SHA-256 list; the same filter ran against the three source directories. Files were
matched by their position inside each component (`vision/` ↔ `/home/pi/abc20261102`, `acoustic/`
↔ `/home/pi/mm_audio_v1`, `environment/` ↔ `/home/pi/env_sensor_v1`). Because the Pi serves LF
files and a Windows checkout carries CRLF, a second normalized comparison stripped carriage
returns before concluding that content differed.

## Notes

- The deployed vision tree is a hybrid: `lab/collection_batches.py`, `lab/local_preview.py` and
  `lab/video_uploads.py` match `revisions/vision-extension/lab/` exactly, while `lab/worker.py`
  and `lab/common.py` match no copy in this repository, and the deployed Supervisor configuration
  runs a `dataset-api` program that has no counterpart under `vision/deploy/`.
- At comparison time the repository carried the base build; since `bf359e7` it carries the Pi
  build. The archived copy stays a reference, not an overlay: do not edit files under
  `deployments/`.
- The GPU and control hosts were not compared in this run; both were captured later, see
  [deployments-20261120.md](deployments-20261120.md).
